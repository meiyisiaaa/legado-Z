## 2. 产品定义

### 2.1 Product Goals（3 个清晰、正交的目标）

| # | 目标 | 正交性说明 |
|---|------|-----------|
| G1 | **降低书源创作门槛** —— 不懂规则语法的普通用户，通过"URL/HTML + 自然语言"即可产出合规书源 JSON | 面向"从 0 到 1"的生成场景 |
| G2 | **降低书源调试成本** —— 现有书源抓不到/抓错时，用户无需深挖规则即可获得诊断与修正 | 面向"从坏到好"的维护场景，与 G1 不重叠 |
| G3 | **零成本、零厂商绑定、可持续** —— 纯本地配置用户自有 API，不新增运营成本与依赖 | 横切 G1/G2 的运行约束，非功能目标 |

### 2.2 User Stories（核心角色场景）

> 覆盖 3 个角色：书源新手（普通读者）、书源老手（维护者）、隐私/成本敏感用户。

- **US1（书源新手）**：As a 想给自己常看的小众网站加书源的普通读者，I want 粘贴网站 URL 并写一句"抓搜索结果、目录、正文"，so that 几分钟内拿到可用书源，而不必学习 Legado 规则语法。
- **US2（书源老手）**：As a 维护多个书源的资深用户，I want 粘贴一个抓不到内容的旧书源 + 测试 URL 让 AI 诊断，so that 快速定位规则错误并获得修正建议/修正 JSON，而不必逐条手工比对。
- **US3（隐私/成本敏感用户）**：As a 不愿泄露数据、不愿被绑定厂商付费的用户，I want 自配本地/自有 OpenAI 兼容 API 且配置绝不联网上报，so that 安心使用 AI 能力而无需担心隐私与账单。

## 3. 技术规范

### 3.1 Requirements Pool（优先级 + 验收标准）

图例：✅ = **沙箱内可跑 JVM 单测**（见设计文档 §7）；❌ = 需本机构建/CI 验证（Android 网络/UI）。

#### P0 — 必备（Must have）

| ID | 需求 | 验收标准（可测试） | 单测 |
|----|------|-------------------|------|
| P0-1 | **AI 配置中心（AiConfig）**：用户可填写并保存 endpoint / apiKey / model / temperature / maxTokens；仅本地存储 | ① 保存后重启 App 配置仍在；② endpoint 为空或格式非法（非 http/https）给出提示且不保存；③ apiKey 为空提示必填；④ 不向任何远端上报配置（代码/网络层可审计） | ✅ AiConfig 校验逻辑 |
| P0-2 | **书源生成主流程（Generate）**：输入 URL 或 HTML 片段 + 自然语言需求 →（可选）OkHttp 抓取 → 截取 HTML 片段控 token → 组装 prompt → 调 LLM → 解析书源 JSON → 按 `BookSource` 结构校验 → 展示 | ① 给定网页片段+意图，能产出结构合法（可被现有 `BookSource` 反序列化）的 JSON；② 必填字段（如 bookSourceUrl/bookSourceName）缺失时给出可理解错误而非静默；③ 超时/401/网络错误降级提示，App 不崩 | ✅ PromptBuilder、SourceGenEngine（JSON 解析+schema 校验）、HTML 片段截取 |
| P0-3 | **书源调试主流程（Debug）**：输入现有书源 JSON + 测试 URL/样例响应 → LLM 诊断 → 返回修正建议或修正后 JSON → 展示 | ① 非法 JSON 源输入给出提示不崩；② 诊断结果明确区分"建议文本"与"可直接导入的 JSON"两类；③ 修正后 JSON 经 `BookSource` 校验通过 | ✅ SourceDebugEngine 的 JSON 解析/校验部分 |
| P0-4 | **一键导入（复用现有链路）**：生成/修正后的书源 JSON 经校验后，调用 `ImportBookSourceDialog(json)` 复用现有书源导入链路，一键导入或覆盖，**零新增导入代码** | ① 调用 `ImportBookSourceDialog(json)`（类位于 `io.legado.app.ui.association`，配套 `ImportBookSourceViewModel`），复用其内建的新增/更新/已有识别、分组管理、保留名称/分组/启用状态、选择性导入，**不写任何新增导入代码**；② 覆盖/更新由该 Dialog 原生确认；③ 导入成功有明确反馈 | ❌ 依赖 Android 导入链路 UI（但仅做调用，无需自写导入逻辑） |
| P0-5 | **错误处理与降级**：LLM 调用失败 / 超时 / 鉴权错误 / 返回非法 JSON，必须明确提示并保留用户输入可重试，App 不崩溃 | ① 各类错误均有明确文案（非异常堆栈）；② 输入框内容保留可重试；③ 无未捕获异常导致崩溃 | ✅ 解析/校验失败分支可单元覆盖 |

#### P1 — 重要（Should have）

| ID | 需求 | 验收标准 | 单测 |
|----|------|---------|------|
| P1-1 | **HTML 片段智能截取与 token 估算**：整页 HTML 据意图截取相关片段并估算 token 上限截断 | ① 超大页面被截断到可配上限；② 截取保留标签闭合/结构完整度，避免残缺标签 | ✅ 截取逻辑 |
| P1-2 | **结果对比/预览**：展示生成的书源 JSON 关键规则（ruleSearch/ruleToc/ruleContent/ruleBookInfo 等）及可读说明 | ① 规则字段分组展示；② 可一键复制完整 JSON | ❌ UI 展示 |
| P1-3 | **请求可取消**：基于现有 OkHttp + 协程，用户可取消抓取/生成过程 | ① 取消后释放协程与连接；② UI 回到可操作态 | ⚠️ 请求构造可 mock 单测，取消逻辑需 Android |
| P1-4 | **配置连通性测试**：配置页提供"测试连接"按钮，用用户配置发最小请求验证可用性 | ① 成功/失败明确反馈；② UI 不回显 apiKey 明文 | ❌ 需网络/UI |

#### P2 — 可选（Nice to have）

| ID | 需求 | 验收标准 | 单测 |
|----|------|---------|------|
| P2-1 | **常用意图模板**：生成页提供"抓搜索/目录/正文/书籍信息"快捷按钮 | ① 点击填充自然语言模板；② 可编辑 | ❌ UI |
| P2-2 | **历史会话**：本地保存最近 N 次生成/调试结果，便于回看复用 | ① 列表可点开；② 可删除；③ 不存隐私内容 | ❌ 依赖本地存储 UI |
| P2-3 | **导出/复制书源 JSON**：结果可导出文件或复制分享 | ① 导出文件可被标准导入识别 | ❌ UI |
| P2-4 | **多 URL 批量生成**：一次对多个 URL 尝试生成并汇总 | ① 逐个执行；② 单项失败不影响其余 | ⚠️ 编排逻辑可单测，UI 需 Android |

### 3.2 UI 设计稿

#### 3.2.1 关键界面交互流（Mermaid）

```mermaid
flowchart TD
    A[书源管理页 / 设置 入口: AI 书源助手] --> B{已配置 API?}
    B -- 否 --> C[打开 AiConfig 配置页\n填写 endpoint/apiKey/model/temp/maxTokens]
    C --> C1[保存本地 + 可选测试连接]
    C1 --> F
    B -- 是 --> F{选择 生成 / 调试}
    F --> G[生成 Tab]
    F --> H[调试 Tab]

    subgraph G2[生成]
        G --> G1[输入: URL 或 粘贴HTML\n+ 自然语言意图]
        G1 --> G2[可选 OkHttp 抓取 → 截取HTML片段]
        G2 --> G3[PromptBuilder 组装 → OpenAiClient]
        G3 --> G4[SourceGenEngine: 解析JSON + BookSource校验]
        G4 --> G5{校验通过?}
        G5 -- 否 --> G6[展示错误 + 可重试/改输入]
        G5 -- 是 --> G7[规则预览 + 一键导入]
    end

    subgraph H2[调试]
        H --> H1[粘贴 现有书源JSON\n+ 测试URL/样例]
        H1 --> H2[SourceDebugEngine: 诊断]
        H2 --> H3[返回: 诊断建议 / 修正JSON]
        H3 --> H4[规则预览 + 一键导入/覆盖]
    end

    G7 --> I[调用 ImportBookSourceDialog(json)\n复用内建导入/更新/分组]
    H4 --> I
    I --> J[导入成功反馈]
```

  └───────────────────────────────────────┘

**交互要点**：
- 入口放在「书源管理」列表页（待确认具体位置，见 §3.3 Q7）。
- 配置页复用 `Server`/`HttpTTS` 的"用户自配远端"UI/存储范式，apiKey 输入框设为 password 类型不回显。
- 生成/调试共用同一结果展示组件（规则预览 + 导入按钮），保证导入行为一致。
- 任何 LLM 失败均保留上方输入，提供"重试"而非清空。

### 3.3 待确认问题（Open Questions — 需用户/团队拍板）

| # | 问题 | 影响范围 | 建议默认 |

| Q4 | **生成失败兜底**：LLM 输出 JSON 不合法时，是否提供"换模型重试 / 用户手动改 JSON 再校验"？ | P0-5 体验 | 提供重试 + 允许手动编辑后本地校验 |

## 4. 范围边界（明确不做，v1 之外）

- ❌ 检索问答 + 选中赏析（读者向，已验证高价值，作为 v1 后自然跟随）
- ❌ 人物/剧情图谱
- ❌ AI 听书旁白
- ❌ 全书级 RAG 摘要

## 5. 隐私与成本基线（贯穿所有需求）

- 仅发送网页片段 + 用户意图（或现有源 + 样例），**不发送书籍正文、不发送用户隐私**。
- 配置**仅存本地**，不上报任何服务端。
- 失败 / 超时 / 鉴权错误给**明确降级提示，App 不崩溃**（P0-5）。
